## WHAT

The contract at the heart of the work model: a System generates work; a
Project contains it. A System is a loop — persistent, judged by health,
spawning cards on its rhythm, never ending until deliberately uprooted.
A Project is a line — bounded, judged by progress, holding a changing
set of cards, ending in the archives. Sprint, user story, or multi-task
initiative are not structural levels; they are all just Projects.

## WHY

Keeping the two shapes distinct keeps both of their measures honest. A
project asks "am I done?" and a system asks "is it healthy?" — collapse
them and recurring obligations masquerade as never-finishing projects
while real projects lose their finish line. The contract was carried
whole from the Lifebuild research, where it was already built and
proven, then ratified for this company's work.

## WHERE

Everywhere work is shaped: the two entity kinds on the map, the two
room designs behind their tiles, and the join every
[[Entity - Work Item]] card carries.

## HOW

The two shapes feed each other in a loop: an [[Entity - Work Project]]
can build and plant an [[Entity - System]] (notice the need, build it
as a project, plant it when the project completes), and a System is
improved by upgrade Projects that end while it continues. Systems
spawn cards; projects collect them; strays belong to neither and pile
where everyone can see them.
