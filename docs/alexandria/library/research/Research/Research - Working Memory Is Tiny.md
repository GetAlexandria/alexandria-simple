## WHAT

A person can hold only a small handful of patterns in mind at once — nowhere near enough
to carry a mental model for every task, in every project, across every part of a company.
That ceiling does not move because the company gets bigger or the software gets smarter;
it is a fixed limit on what a single head can carry, which means anything beyond a handful
of patterns has to live somewhere other than inside a person's own memory if it is going
to be usable at all.

## WHY

This lesson matters because it turns externalizing company knowledge into an obligation
rather than a convenience: if working memory truly cannot stretch to cover an
organization's real complexity, then a library that holds what no single head can is not
an optional nicety layered on top of how work already gets done, it is the only way the
work stays tractable at all as a company grows past what one person could ever keep in
mind.

## WHERE

This lesson is the cognitive-science reason a library must exist as a
[[Bet - Library as Living Source of Truth|living source of truth]] — an external
place for company knowledge, rather than a set of notes each person is trusted to
hold in their head.

It rhymes directly with a lesson drawn from an entirely different corpus — that attention
itself is a scarce resource high-reliability organizations must engineer for rather than
assume — which arrives at the same conclusion about the limits of a single mind from a
different direction.
