two-axis **families taxonomy** (type), with status + altitude — versus the Engine view's
**DDD / context** sort. The decision you named: **is the new view simply "an alternative

- Both are projections of the **same two-axis data**, so the cleanest answer is likely
  **one library, multiple sorts** — by type/families, by context, by altitude, by status.
- Productize the walk's readability (name-first chips, def-lists, status treatment, the
