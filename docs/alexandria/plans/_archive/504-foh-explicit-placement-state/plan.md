# Issue #504: Front-of-House Explicit Placement State

## Header

Issue reference: GitHub issue `#504`, "Model Front-of-House placement state
explicitly (retire the unfiled/framing string sentinel)".

Goal: replace the Front-of-House agenda's magic placement strings with an
explicit typed placement state, so filed/unfiled/framing status is no longer
inferred from `context` or `plane` values. `confirm-section` must derive a
section plane from filed items only, while real authored names such as
`"unfiled"` or `"framing"` remain valid context or plane strings.

Linked product plan: none supplied. The issue body is the binding product
contract for this slice. Historical input plans reviewed:
`docs/alexandria/plans/480-front-of-house-table-agenda/plan.md`, which
introduced the current sentinel placement fallback, and
`docs/alexandria/plans/484-foh-held-back/plan.md`, which relies on the current
agenda ordering and `confirm-section` helpers.

Planning note: the GitHub CLI is not installed in this environment, so the
issue body provided in the planning request is the issue source reviewed here.

## Scope

This slice changes the Front-of-House agenda placement model and its direct
consumers.

In scope:

1. In `packages/ax/src/domain/library-front-of-house.ts`, introduce an explicit
   agenda placement state, for example:

   ```ts
   export const FRONT_OF_HOUSE_AGENDA_PLACEMENT_STATES = [
     "filed",
     "unfiled",
     "framing",
   ] as const;

   export type FrontOfHouseAgendaPlacementState =
     (typeof FRONT_OF_HOUSE_AGENDA_PLACEMENT_STATES)[number];
   ```

2. Add `placementState: FrontOfHouseAgendaPlacementState` to
   `FrontOfHouseAgendaItem`.
3. Keep `context` and `plane` as optional top-level agenda item fields that
   contain only genuine authored/resolved names. They must never carry
   `"unfiled"` or `"framing"` as a status sentinel. A filed item must have both
   fields. An unfiled item may retain a genuine partial `context` or `plane` if
   only one side resolved, and omits whichever side did not resolve. A framing
   item uses `placementState: "framing"` instead of fake `context`/`plane`
   values.
4. Bump the runtime agenda/current-item schema version for this incompatible
   JSON shape, or introduce an equivalent explicit version constant, so stale
   sentinel-shaped runtime files fail clearly and can be regenerated by
   `prepare-agenda`.
5. Replace `FRONT_OF_HOUSE_UNFILED` and `FRONT_OF_HOUSE_FRAMING` sentinel
   constants with typed state/display helpers.
6. Update placement projection from threads/concerns so unresolved placement is
   represented by `placementState: "unfiled"` and absent/partial genuine fields,
   not by sentinel strings.
7. Update all agenda consumers in `library-front-of-house.ts`:
   `isUnfiledAgendaItem`, `agendaFiledRank`, `compareAgendaProjections`,
   placement display/markdown rendering, current-item rendering,
   residual-gap projection/rendering, section item lookup, and
   `deriveSectionPlaneForContext`.
8. Update `confirm-section` behavior through the domain helpers it already
   calls: a context with one real filed plane plus unfiled same-context items
   must confirm successfully; a context with two real filed planes must still
   fail as ambiguous.
9. Narrow `FrontOfHouseAgendaItem.sourcePath` to the single literal
   `"threads.json"` and remove parser validation branches for
   `"STAGE-2-BRIEF.md"` and `"HOT-SPOTS.md"`.
10. Update deterministic AX tests and black-box Front-of-House CLI tests for
    the acceptance matrix.
11. Update the shipped `front-of-house-walk` skill only as needed to describe
    the explicit placement contract when it reads `current-item.json` and
    `agenda.json`. The workflow prompt that permits Raven to correct card
    `context` and `plane` remains valid; this issue changes agenda placement
    state, not allowed card update fields.

## Current Gap

`FrontOfHouseAgendaItem` currently requires `context: string` and
`plane: string`. Placement resolution writes the literal string `"unfiled"`
into those fields when a context or plane cannot be resolved, and writes
`"framing"` into both fields for frame-origin agenda items. Consumers then
reconstruct item status by comparing those strings.

That overloading is already visible in these paths:

1. `placementFromConcern` and `placementFromThread` return
   `{ context: "unfiled", plane: "unfiled" }` or
   `{ context: "framing", plane: "framing" }`.
2. `isUnfiledAgendaItem` detects unfiled status by checking whether either
   placement field equals `"unfiled"`.
3. `agendaFiledRank` and `compareAgendaProjections` depend on that inferred
   status to sort filed items before unfiled items inside each movement.
4. `displayPlacementValue` maps sentinel strings back to the director-visible
   `Unfiled` and `Framing` labels.
5. `parseFrontOfHouseAgenda` supplies `"unfiled"` defaults for missing legacy
   `context` and `plane`.
6. `deriveSectionPlaneForContext` does not special-case the sentinel, so it can
   derive the distinct plane set `["product", "unfiled"]` and reject a section
   that is actually single-plane plus unresolved agenda work.

The same area still types `sourcePath` as
`"STAGE-2-BRIEF.md" | "HOT-SPOTS.md" | "threads.json"` even though fresh agenda
projection only writes `"threads.json"`.

## Architectural Boundaries

`packages/ax` owns the deterministic runtime artifact and command behavior.
The placement state belongs in the pure domain projection and parser layer, not
in `confirm-section` command code. `runConfirmSection` should keep reading the
agenda and delegating section derivation to `library-front-of-house.ts`.

The agenda JSON is a derived runtime artifact under
`runtime/front-of-house/agenda.json`; it is not a durable Ledger event. Because
the new shape removes overloaded required strings, the implementation should
make the runtime schema version explicit and reject stale sentinel-shaped
runtime files with an error that tells operators to rerun `prepare-agenda`.
Avoid lossy legacy parsing that reintroduces `"unfiled"` or `"framing"` as
magic values; a v1 file cannot distinguish a sentinel from a real authored name.

The agenda item compatibility boundary is:

1. `placementState` is the only source of filed/unfiled/framing status.
2. `context` and `plane` are optional and, when present, are real names.
3. `placementState: "filed"` requires non-empty `context` and `plane`.
4. `placementState: "unfiled"` requires at least one unresolved side and may
   retain any genuine resolved partial field.
5. `placementState: "framing"` is distinct from a filed item whose real context
   or plane happens to be named `"framing"`.

The shipped plugin owns guided play behavior. If the implementation changes how
Raven should read placement from `current-item.json` or `agenda.json`, update
`packages/alexandria-plugin/skills/front-of-house-walk/SKILL.md` in the same
slice and validate the plugin. Keep the skill wording generic: it should say to
use filed items' `context` and `plane` for section comprehension and not treat
unfiled/framing state as a real section.

## Risks And Mitigations

| Risk | Mitigation |
| --- | --- |
| Optional `context`/`plane` fields create accidental non-null assumptions in renderers or section helpers | Add small placement helper functions, for example `isFiledAgendaItem`, `agendaItemContext`, `agendaItemPlane`, and `formatAgendaPlacement`, and route all consumers through them |
| A real authored context named `"unfiled"` or `"framing"` is still treated as status somewhere | Remove sentinel constants, reject parser paths that infer state from those strings in the new schema, and add collision tests with `placementState: "filed"` plus literal names |
| `confirm-section` starts ignoring real multi-plane ambiguity while ignoring unfiled items | Filter only `placementState === "filed"` for the plane set and keep the existing multi-plane error when the filed set has more than one plane |
| A context has no filed items after filtering and `confirm-section` chooses an arbitrary fallback | Return a semantic invalid-input error such as `Front-of-house context "X" has no filed plane to confirm.` Cover this negative case if it is easy to express |
| Stale runtime `schemaVersion: 1` files fail after the shape change | Treat agenda/current-item files as derived artifacts, fail with a clear rerun-`prepare-agenda` message, and cover fresh `prepare-agenda` output in black-box tests |
| Plugin skill wording drifts from the runtime JSON contract | Update `front-of-house-walk/SKILL.md` in the same slice if runtime JSON field guidance changes; run plugin validation and update the structural eval config |
| Residual-gap markdown loses placement labels for unfiled/framing items | Keep display helpers state-aware and assert `Unfiled`/`Framing` labels in unit or bundle tests |
| SourcePath narrowing leaves stale parser branches or fixtures | Type `sourcePath` as `"threads.json"`, remove STAGE/HOT parser branches, and search for old sourcePath literals after implementation |

## Implementation Steps

1. Add explicit placement state types and helpers in
   `packages/ax/src/domain/library-front-of-house.ts`.
   Suggested helpers:
   `isFiledAgendaItem(item)`,
   `isUnfiledAgendaItem(item)`,
   `isFramingAgendaItem(item)`,
   `placementPlane(item)`,
   `placementContext(item)`, and
   `formatAgendaPlacement(item)`.

2. Update `FrontOfHouseAgendaItem`:
   add `placementState`;
   change `context` and `plane` to optional genuine-name fields;
   narrow `sourcePath` to `"threads.json"`;
   update `FrontOfHouseAgenda`, `FrontOfHouseCurrentItem`, and related render
   types to use the new schema/version shape.

3. Replace placement projection:
   change `placementFromConcern` so it returns a typed placement candidate with
   genuine partial fields instead of sentinel fallback values. A concern with
   both context and plane becomes `placementState: "filed"`. A concern with
   only one genuine side becomes `placementState: "unfiled"` plus that partial
   field. A concern with neither side becomes `placementState: "unfiled"` with
   no `context` or `plane`.

4. Update `placementFromThread`:
   frame-origin items return `placementState: "framing"`;
   normal items prefer the first filed concern placement;
   if none are filed, keep the first partial unfiled placement when available;
   otherwise return a fully unfiled placement. This preserves useful genuine
   context for same-context grouping without inventing a plane.

5. Update agenda sorting:
   keep frame items first;
   within non-frame movement ranks, sort filed items before unfiled items using
   `placementState`;
   compare plane/context only for filed items;
   keep existing severity, thread kind, title, id, and original index
   tie-breakers.

6. Update display/rendering:
   replace `displayPlacementValue(value: string)` with a state-aware placement
   formatter. Preserve current labels:
   filed `product`/`board` renders `Product -> Board`;
   unfiled with no fields renders `Unfiled -> Unfiled`;
   unfiled with known context and missing plane renders `Unfiled -> <Context>`;
   framing renders `Framing -> Framing`.

7. Update parsing:
   parse only the explicit placement-state schema for the new runtime version;
   validate that filed items have both `context` and `plane`;
   validate that unfiled/framing items do not need sentinel strings;
   accept only `sourcePath: "threads.json"`;
   remove `"STAGE-2-BRIEF.md"` and `"HOT-SPOTS.md"` sourcePath branches.

8. Update section helpers:
   change `sectionAgendaItemsForContext` to match items with a genuine
   `context` equal to the requested context and to exclude framing state unless
   it is deliberately represented as a filed real context;
   build the known-context list from genuine contexts only;
   change `deriveSectionPlaneForContext` to collect planes only from filed
   matched items.

9. Preserve `confirm-section` command structure:
   let existing `runConfirmSection` continue to call
   `deriveSectionPlaneForContext`, `deriveSectionCardsForContext`, and
   `deriveSectionUnknownsForContext`;
   add or update black-box tests to prove the CLI returns exit `0` and JSON
   `plane: "product"` for a single real filed plane plus same-context unfiled
   item, and exit `2` with the ambiguity message for two real filed planes.

10. Update residual handling:
    change `FrontOfHouseResidualGap` and `unresolvedFrontOfHouseGaps` to carry
    either the new placement fields or enough state for `formatAgendaPlacement`;
    keep residual Ledger events unchanged because they only store item id, kind,
    run, bundle, and reason.

11. Update tests in `packages/ax/tests/library-front-of-house.test.ts`:
    projection creates explicit `placementState` values;
    no generated unfiled/framing item stores sentinel strings in `context` or
    `plane`;
    real context named `"unfiled"` with a real plane is filed and confirmable;
    framing sorts/renders as `Framing`;
    agenda ordering remains frame first, filed before unfiled within movement,
    canonical plane/context refinement for filed items, and stable tie-breaks;
    projection is idempotent for the same thread input.

12. Update tests in `packages/ax/tests/library-front-of-house-bundle.test.ts`:
    `prepare-agenda` writes only `sourcePath: "threads.json"`;
    bundle helpers stop detecting unfiled status by string comparison;
    current-item and Raven markdown keep `Unfiled`/`Framing` labels;
    `confirm-section` acceptance and negative cases run through the real CLI.

13. If the runtime JSON guidance changes for Raven, update
    `packages/alexandria-plugin/skills/front-of-house-walk/SKILL.md` to say
    `placementState: "filed"` gates section comprehension coordinates. Update
    `packages/ax/tests/eval-cases/front-of-house-walk/section-comprehension-contract/config.json`
    if its structural strings need to follow the new wording.

14. Run the deterministic verification commands and any applicable plugin/eval
    checks from this plan. Search for stale sentinels and dead sourcePath
    branches before finishing:
    `rg -n "FRONT_OF_HOUSE_UNFILED|FRONT_OF_HOUSE_FRAMING|STAGE-2-BRIEF.md|HOT-SPOTS.md|context === \"unfiled\"|plane === \"unfiled\"" packages/ax packages/alexandria-plugin`.

## Acceptance / Exit Criteria

1. `confirm-section --context X` succeeds with exit code `0` and derives
   `plane: "product"` when the matched section contains one or more filed
   product items plus same-context unfiled items.
2. `confirm-section --context X` still fails with exit code `2` and a
   multi-plane ambiguity message when filed matched items span two real planes,
   for example `product` and `learning`.
3. A filed agenda item whose real context is literally `"unfiled"` is treated
   as context `"unfiled"`, not as unfiled state, and can be confirmed with its
   real plane.
4. A filed agenda item whose real context or plane is literally `"framing"` is
   distinguishable from `placementState: "framing"`.
5. Fresh agenda projection never writes `"unfiled"` or `"framing"` as fake
   `context` or `plane` values.
6. `FrontOfHouseAgendaItem.sourcePath` is typed as `"threads.json"` only, and
   typecheck passes without STAGE/HOT assignment or validation branches.
7. Re-deriving placement for the same agenda input yields the same
   `placementState`, `context`, and `plane` fields, and replaying
   `confirm-section` produces the same result.
8. Agenda ordering is unchanged in user-observable ways: framing first,
   comprehension before held-back hot spots, filed before unfiled within each
   movement, filed items refined by canonical plane and context, and stable
   tie-breaks.
9. Rendered placement labels remain unchanged for users:
   `Unfiled` and `Framing` still appear in current-item/Raven/residual markdown
   where they appeared before.
10. AX unit tests, AX black-box bundle tests, typecheck, lint/format checks,
    and any applicable plugin validation/eval checks pass or have documented
    environment-only blockers.
