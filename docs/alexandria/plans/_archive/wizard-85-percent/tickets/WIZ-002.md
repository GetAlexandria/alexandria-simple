## Motivation

Users default to "we're unique" (everyone thinks their product is novel) or "we're
normal" (impostor syndrome about novelty). A gentle nudge toward Moderate using
observable signals catches both failure modes without requiring abstract re-evaluation.

## Description

After the user answers Q2 (Domain Novelty), apply a directional sanity check:

**If Low:** "Quick check — when you onboard a new team member, how long before they
stop saying 'oh, I assumed it would work like [familiar product]'? If that's more than
a week, you might be Moderate."

**If High:** "Quick check — do you have any direct competitors, even bad ones? If yes,
your domain has a category forming — you might be Moderate."

**If Moderate:** No bump (already in the middle).

**Files to modify:**
- `skills/wizard/SKILL.md` — Step 1, after Q2 answer
- `docs/wizard/wizard-engine.yaml` — questions section, Q2 guidance/disambiguation

## Acceptance Criteria

- [ ] After answering Low or High on Q2, user sees a gentle disambiguation bump
- [ ] Bumps use observable signals (onboarding time, competitor existence)
- [ ] User can accept the bump or keep their original answer
- [ ] No engine changes — the final Low/Moderate/High value is passed as before
- [ ] Existing QA wizard tests pass unchanged
