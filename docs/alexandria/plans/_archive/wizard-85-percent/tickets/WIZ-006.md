## Motivation

The Q3 checklist mapping (count → Low/Moderate/High) is a new piece of logic that
needs deterministic test coverage. The engine is untouched, but the mapping layer
between the checklist and the engine must be verified.

## Description

Add test cases to the QA suite verifying that the checklist count maps correctly
to complexity levels and that the resulting configurations match expectations.

**Test cases:**
- 0 items checked → Low
- 1 item checked → Low
- 2 items checked → Moderate
- 3 items checked → Moderate
- 4 items checked → High
- 5 items checked → High
- 6 items checked → High
- Boundary: exactly 2 → Moderate (not Low), exactly 4 → High (not Moderate)

**Calibration checks:**
- 3-5 real product profiles with known "correct" complexity, verify the checklist
  produces the right answer

**Files to modify:**
- `tests/qa-wizard.sh` — add new test section for checklist mapping

## Acceptance Criteria

- [ ] All count-to-level mappings verified (0-6 items)
- [ ] Boundary cases tested (1→Low, 2→Moderate, 4→High)
- [ ] Existing QA wizard tests still pass
- [ ] At least 3 calibration profiles documented

## Implementation Notes

- These are deterministic tests, not LLM-as-Judge
- Can be added as a new section in the existing qa-wizard.sh
- Calibration profiles should be documented in the test file as comments
