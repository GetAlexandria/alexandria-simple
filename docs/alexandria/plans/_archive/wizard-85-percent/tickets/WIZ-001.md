## Motivation

Q3 ("how many features does a decision affect?") directly asks for systems reasoning.
Non-systems-thinkers systematically underestimate and answer "Low." Replacing with a
binary checklist of observable signals lets the checklist do the systems thinking.

## Description

Replace the current Q3 question in the wizard with a checklist of observable complexity
signals. The user checks all that apply; the count maps to Low/Moderate/High before
the engine sees it.

**Checklist items:**
- Features share data or state (e.g., a user's action in one area shows up in another)
- The product has invisible mechanisms: scoring, recommendations, matching, progression
- Permissions or roles change what people see or can do
- There are workflows that span multiple screens or features
- Changing one feature's rules has broken or surprised another feature before
- The product has an internal economy, points, or resource system

**Mapping:** 0-1 → Low, 2-3 → Moderate, 4+ → High

**Files to modify:**
- `skills/wizard/SKILL.md` — Step 1, Q3 presentation and mapping logic
- `docs/wizard/wizard-engine.yaml` — questions section, Q3 text and options

**Engine is untouched** — it still receives Low/Moderate/High. The mapping happens in
the skill layer before passing to the engine.

## Acceptance Criteria

- [ ] Q3 presents a checklist of 6 observable signals instead of an abstract question
- [ ] Checklist count maps to Low (0-1), Moderate (2-3), High (4+)
- [ ] Engine receives the same Low/Moderate/High values as before
- [ ] All 36 configuration tables produce identical tier assignments
- [ ] Existing QA wizard tests pass unchanged
