## Motivation

Even with better questions, some users will miscalibrate. A cheap empirical check —
"do these problems sound familiar?" — catches mismatches before investing in gap
analysis. This is a safety net.

## Description

Add a confirmation step between the configuration summary (Step 4) and gap analysis
(Step 5). Show Foundation area problems and ask if they ring true.

**Confirmation text:**
> "Does this ring true? Look at your Foundation areas. If you've seen the problems
> described in 'Why It Matters' happen on your team, the configuration is well-
> calibrated. If those problems sound unfamiliar, your answers to the three questions
> may need adjusting — say 'reconfigure' to go back."

If the user says "reconfigure," return to Step 1 with their previous answers as
defaults.

**Files to modify:**
- `skills/wizard/SKILL.md` — Step 4, after summary, before gap analysis prompt

## Acceptance Criteria

- [ ] After Step 4 summary, user sees a "does this ring true?" confirmation
- [ ] Foundation area problems from when_missing are surfaced
- [ ] User can say "reconfigure" to return to questions with previous answers as defaults
- [ ] If user confirms, proceed to gap analysis as normal
- [ ] No engine changes
- [ ] Existing QA wizard tests pass unchanged
