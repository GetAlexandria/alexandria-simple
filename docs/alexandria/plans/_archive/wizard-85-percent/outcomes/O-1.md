## Validation Criteria

- A user who doesn't naturally trace ripple effects across features still arrives at
  the correct Low/Moderate/High complexity classification for their product
- The checklist-based Q3 and disambiguation bumps on Q2 produce the same tier
  assignments as a systems-thinker answering the original questions for the same product
- All 36 existing configuration tables produce identical tier assignments (engine untouched)

## Motivation

Q3 ("how many features does a decision affect?") directly requires systems reasoning —
the thing ~85% of users can't do. They systematically underestimate complexity and
answer "Low." The fix: replace the abstract question with observable binary signals
(shared state? permissions? invisible mechanisms?) and add gentle disambiguation bumps
to Q2. The checklist does the systems thinking so the user doesn't have to.
