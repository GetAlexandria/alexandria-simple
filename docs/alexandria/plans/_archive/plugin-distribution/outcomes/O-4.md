## Validation Criteria

- Tagging a release (`git tag v0.7.0 && git push --tags`) in the context-library repo triggers a CI workflow
- The workflow builds the stripped tarball and publishes it as a GitHub Release artifact
- The tarball and `latest-version.txt` are deployed to `sociotechnica.org/alexandria/`
- `https://sociotechnica.org/alexandria/latest-version.txt` returns the current version string
- `https://sociotechnica.org/alexandria/alexandria-v{VERSION}.tar.gz` downloads the tarball

## Motivation

Manual releases are error-prone and create a bottleneck. Automated CI ensures every
tagged version is consistently built, stripped, and published to the download site.
This also keeps `latest-version.txt` in sync, which the install script and
update-check tool depend on.
