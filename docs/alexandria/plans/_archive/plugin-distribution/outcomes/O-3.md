## Validation Criteria

- When `CLAUDE_PLUGIN_DATA` is set, compiled binaries are built to `${CLAUDE_PLUGIN_DATA}/bin/.compiled/`
- When `CLAUDE_PLUGIN_DATA` is set, state/cache files are stored in `${CLAUDE_PLUGIN_DATA}/`
- Bin wrapper scripts resolve compiled binaries from `${CLAUDE_PLUGIN_DATA}` first, falling back to the current `bin/.compiled/` path
- Existing installs without `CLAUDE_PLUGIN_DATA` continue to work unchanged
- After a plugin update (new tarball extracted over old), compiled binaries still exist and work

## Motivation

`${CLAUDE_PLUGIN_ROOT}` changes on plugin updates, so anything stored there is
lost. Claude Code provides `${CLAUDE_PLUGIN_DATA}` as a persistent directory
specifically for this purpose. Moving compiled binaries there means updates don't
require re-compilation, and state (update-check cache) isn't lost.
