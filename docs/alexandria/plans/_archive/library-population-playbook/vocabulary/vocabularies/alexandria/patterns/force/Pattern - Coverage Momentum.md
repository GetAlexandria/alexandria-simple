# Coverage Momentum

## WHAT: Definition

_Stub — Coverage Momentum is the emergent behavior where Bridget's assembly gaps drive Sam's build queue, which fills those gaps, which improves future assemblies, which produces better factory output, which generates more assembly requests, which reveals new gaps. The library grows in the direction of actual demand rather than theoretical completeness. This is not a designed repeating cycle but an emergent cross-system pattern: Bridget serves honestly, the Feedback Queue accumulates, and Sam builds what the factory needs most. The full existing card is at [[Force - Coverage Momentum]] in the existing library._

_Note on category: the existing library calls this a "Force" (design-thinking terminology for emergent system dynamics). In the Vocabulary framework, Pattern is the closest fit — it is a recurring dynamic with a predictable structure. The Force category has no equivalent in the 10-category framework; the flag is documented in the README._

## WHERE: Ecosystem

_Stub — links to: [[Force - Coverage Momentum]] (full card), [[Role - Bridget the Briefer]] (initiates the cycle via gap logs), [[System - Feedback Queue]] (accumulates the demand signal), [[Role - Sam the Scribe]] (builds in response to the signal)._

## HOW: Specification

_Stub — Coverage Momentum is self-reinforcing but not self-sustaining. It requires the factory to be running (generating assembly requests) and Bridget to be logging gaps honestly. If either stops, the signal dries up and Sam builds from theoretical completeness instead of real demand._
