# Cycle (recurring rhythm)

## WHAT: Definition

_Stub — the recurring time-box rhythm Teams adopt: typically 1–4 weeks, with Issues scoped to at most one active Cycle. The rhythm is the Pattern — the repeating cadence of plan, commit, complete, review, repeat — that Teams establish around Cycles as objects._

_This card documents a deliberate dual-facet split: [[Entity - Cycle]] is the addressable noun-object — the named, dateable thing a Team creates and closes. [[Pattern - Cycle]] is the recurring rhythm — the organizational behavior Teams develop around those objects. Same word, two facets. The Entity card answers "what is a Cycle?"; this Pattern card answers "what does running Cycles look like as a team practice?" This split is the model for how the families.md framework handles concepts that are simultaneously a thing-you-create and a behavior-you-adopt. Cross-reference [[Entity - Cycle]] for the object semantics._

## WHERE: Ecosystem

_Stub — links to: [[Entity - Cycle]] (the Entity facet of the same concept), [[Entity - Team]] (Teams are the unit that adopts the Cycle rhythm), [[Entity - Issue]] (Issues are the unit of commitment within each Cycle), [[Pattern - Backlog]] (the queue Pattern that feeds each new Cycle's commitment)._
