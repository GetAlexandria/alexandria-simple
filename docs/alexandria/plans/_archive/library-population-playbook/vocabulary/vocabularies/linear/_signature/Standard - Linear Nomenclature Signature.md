# Linear Nomenclature Signature

## WHAT: Definition

The naming style this product commits to. New nouns proposed by Sam, Raven, or any maintainer get linted against this signature; violations require a deliberate override.

The signature has six rules, inferred from Linear's existing public vocabulary:

1. **Short, common-English nouns.** One or two syllables preferred. (Issue, Cycle, Team, View, Inbox — not "WorkItem," "TimeBox," "WorkstreamView.")
2. **Process-neutral over process-borrowed.** Use Cycle, not Sprint. Use Triage, not Backlog Grooming. The product is sold across team types; process-vocabulary that fits engineering doesn't fit the rest.
3. **Container nouns are concrete.** Workspace, Team, Project — not "Org," "Group," "Folder." Concrete > abstract.
4. **Item nouns name the work, not the tracking mechanism.** Issue (not "Ticket," not "Story"). Issue is what the user IS encountering; Ticket is what a tracking system records.
5. **Capability verbs are gerunds.** Filtering, Assigning, Triaging — not "Filter" as a noun on a menu. (Linear softens this in the UI; the underlying convention is gerund.)
6. **Surfaces are display-mode-named.** View, Inbox, Dashboard — named for what the user does there (look, receive, monitor), not for the data backing them.
