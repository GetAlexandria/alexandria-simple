# Messaging

## WHAT: Definition

_Stub — the in-platform communication action available to both [[Role - Guest|Guests]] and [[Role - Host|Hosts]]: sending [[Entity - Message|Messages]] within a [[Entity - Thread]] to the other party. Messaging is the shared Capability that enables pre-booking questions ([[Entity - Inquiry]]), booking coordination, check-in logistics, and post-stay follow-up. Airbnb strongly encourages keeping communication in-platform (vs external channels) because [[Role - Customer Support]] uses Message history as evidence in disputes._

## WHERE: Ecosystem

_Stub — links to: [[Entity - Message]] (the artifact Messaging produces), [[Entity - Thread]] (the conversation container Messaging operates within), [[Entity - Inquiry]] (the pre-booking Message type that initiates a Thread), [[Pattern - Communication Thread]] (the two-audience pattern Messaging implements)._

## WHY: Rationale

_Stub — owner-supplied._

## WHEN: Timeline

_Stub._

## HOW: Specification

_Stub — to be enriched with: Messaging access points (from Listing Detail Page before booking; from Trip / Reservation card after booking); automated message templates Hosts can configure; push notifications and email notification routing; Airbnb's content moderation of Messages; the policy on sharing external contact information before booking confirmation._
