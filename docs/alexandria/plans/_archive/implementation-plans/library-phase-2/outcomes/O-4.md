## Validation Criteria

- Session-start procedure reads alexandria-config.json + library state and renders current scoreboard
- Scoreboard reflects state changes made outside the `/library` room since the last session (new cards, Conan grades, source material additions)
- Raven distinguishes first-time vs returning users and adjusts opening accordingly
- Returning users see a "here's what changed since we last talked" summary when the library has meaningfully changed
- When library state has regressed (e.g., Conan flagged cards that previously passed), Raven surfaces this without derailing the session
- Greenfield-to-brownfield transition is handled: a user who shipped code since their first session is routed appropriately, not re-routed through first-time onboarding

## Motivation

Session continuity is the property that makes `/library` a persistent room rather than a one-time command. Without it, every session starts from zero — Raven re-asks settled questions, ignores progress made outside the room, and fails to give users the "pick up where we left off" experience that makes the iterative model valuable.

The iterative room model only earns its value over multiple sessions. O-4 is the outcome that makes Round 2 and Round 3 sessions meaningfully different from Round 1 — and that makes the scoreboard a trusted artifact rather than a snapshot that drifts from reality.
