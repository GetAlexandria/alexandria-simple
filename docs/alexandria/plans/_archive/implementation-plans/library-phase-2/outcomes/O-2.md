## Validation Criteria

- Scoreboard derivation spec is documented: algorithm for computing fill level (0/25/50/75/100%) per knowledge area from alexandria-config.json + library state
- Fill-level states map to the five lifecycle markers from expert calibration: Nothing / Raw material dumped / Elicitation done / Cards drafted / Functioning
- ASCII renderer produces correct bucket display (Foundation / Core / Amplifier) with bar-fill characters for any valid configuration
- Clearance and unlock messages appear correctly: partial-Foundation clearance, Core-locked message when Foundation < 80%
- Derivation is runnable at any time without a live `/library` session — reconstructible from state on disk
- Tested against representative configurations: Factory-High, Short-Order-Cook-Low, Pair-Programmer-Medium

## Motivation

The scoreboard is the persistent artifact at the center of the `/library` room. It is what Raven reads at session start, what she references in stopping-point calls, and what makes progress visible across sessions. If the scoreboard is wrong, Raven gives wrong guidance. If it is unrenderable, the session has no shared reference.

Derivation from live state (not conversation history) is the key design property: it means the scoreboard is correct even when cards were added by Conan health checks, Sam card builds, or source material additions between sessions. Any agent can update state; Raven reads derived truth at session start.
