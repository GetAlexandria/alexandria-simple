## Validation Criteria

- Raven conducts a full greenfield initialization through conversation — no step numbers or form fields visible to the user
- Raven writes confirmed initialize artifacts directly: alexandria-config.json, initialize-output.md, and assessment.md
- Sam produces valid card-like artifacts from Raven's conversational direction where card structure or later Conan review matters
- Raven presents artifacts to the user for review mid-conversation and incorporates feedback
- Scoreboard updates to reflect new state after artifact production
- Raven issues a stopping-point clearance statement at end of round: specific clearance + "come back when" prompt
- Raven does not write library cards directly at any point in the session

## Motivation

This is the core exit criterion for Phase 2 from the vision document: can Raven complete a full library initialization — configuration, gap analysis, assessment document — through conversation, with the right writer handling each artifact and the scoreboard updating, without the user ever seeing a step-number or a form?

O-3 validates that the Raven-as-orchestrator model works end-to-end. The main boundary is now split: Raven persists initialize artifacts directly, and the Raven→Sam handoff remains the interface for card-like outputs that downstream agents (Conan, Bridget) consume. This outcome cannot be validated by unit tests — it requires running the full workflow.
