## Motivation

The scoreboard is only useful if it renders legibly. The ASCII renderer is the concrete artifact that Raven reads at session start and references throughout the session. Without a renderer, the derivation spec (LIB2-002) produces numbers but no visual.

## Description

Implement the scoreboard renderer. The renderer takes derivation output (fill level per knowledge area, per-tier aggregates, clearance status) and produces ASCII art suitable for the Claude Code terminal interface.

**Target output format (from vision doc):**

```
┌─ FOUNDATION ─────────────────────────────────┐
│ Product Vision     ████████████████████ FULL  │
│ Product Strategy   █████████████░░░░░░  65%   │
│ User Personas      ████████░░░░░░░░░░░  40%   │
│ Noun Vocabulary    ░░░░░░░░░░░░░░░░░░░  0%    │
└──────────────────────────────────────────────┘
  → Foundation partial: cleared for [Vision, Strategy] | need [Personas, Vocabulary] for full clearance

┌─ CORE ────────────────────────────────────────┐
│ User Journey Maps  ░░░░░░░░░░░░░░░░░░░  0%    │
│ System Design      ░░░░░░░░░░░░░░░░░░░  0%    │
└──────────────────────────────────────────────┘
  → Core locked until Foundation >= 80%
```

**Bar fill characters:** `█` for filled, `░` for empty. Five states map to approximately 0/5/10/15/20 filled characters in a 20-character bar width.

**Clearance messages (per bucket):**
- Foundation full: "Foundation complete — cleared to build [list of unlocked capabilities]"
- Foundation partial: "Foundation partial: cleared for [areas at 100%] | need [areas below 100%] for full clearance"
- Core locked: "Core locked until Foundation >= 80%"
- Core unlocked, partial: "Core partial: [areas at 100%] unlocked | [areas below] in progress"
- Amplifier: "Amplifier available — [areas at 100%] active | [areas below] optional"

**Implementation options (choose one):**
- TypeScript function in `src/tools/scoreboard.ts` callable by the wizard CLI
- Inline rendering in Raven's job procedure (Raven constructs the display from derivation output)
- Both: a CLI tool for scripted use + inline procedure text for Raven to follow

The preferred approach is a TypeScript function in `src/tools/` so it can be tested deterministically, plus a description in Raven's job procedure of how to invoke it.

## Context

The renderer must handle the full range of configurations from the wizard engine — from a minimal Short-Order-Cook-Low (few areas, small buckets) to a Factory-High (many areas, large buckets with long names). Bar labels should truncate or align gracefully at different area name lengths.

## Acceptance Criteria

- [ ] Renderer produces correct ASCII output for 0%, 25%, 50%, 75%, 100% fill states
- [ ] Foundation, Core, and Amplifier buckets all render correctly
- [ ] Clearance and lock messages appear in correct positions
- [ ] Renderer handles configurations with 1 area per bucket and configurations with 8+ areas
- [ ] Output is tested with at least two representative configurations
- [ ] If implemented as a TypeScript tool: `bun test` covers the renderer

## Implementation Notes

Unicode box-drawing characters (`┌`, `┐`, `└`, `┘`, `│`, `─`) render correctly in modern terminals and the Claude Code interface. Test that bar characters (`█`, `░`) render without escaping issues. If encoding problems arise, fall back to `#` and `.` characters with a note that the target terminal should support Unicode.
