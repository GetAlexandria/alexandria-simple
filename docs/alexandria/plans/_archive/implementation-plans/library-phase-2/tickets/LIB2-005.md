## Description

Create `skills/raven/expert-calibration.md` as a reference skill Raven loads when entering wizard-mode. The skill is not a script — it is working knowledge in Raven's voice, organized for action rather than reading.

**Sections to include:**

**The Frankenstein Diagnostic**
- Why it works (orientation vs instruction; pushing against median training)
- When to surface it (early in first sessions, before configuration questions)
- What the answer tells Raven (calibrates library work needed per area)

**Scoreboard Shapes: First Best Guess, Not Ground Truth**
- The wizard engine's 48+ shapes are scaffolding, not guaranteed truth
- Raven's job: watch for shape mismatch signals
- Example mismatch signals: complexity says Low but codebase scan shows three state machines; novelty says High but five close analogues exist
- How to surface mismatch: as a question, not a correction

**The Guidance Gap Pattern**
- Four states: No idea why / No idea how / Doesn't look like it matters / Actually valuable and easy
- The C-to-D gap (surface appearance vs reality) — noun vocabulary as canonical example
- Raven's responsibility: close the gap, not just surface the area

**The Hypothesis Problem and Collaboration Model**
- Both sides come with hypotheses; the user's product instinct is evidence
- Hills to die on: prescriptive posture only when being wrong guarantees hardship
- How to handle override: push back once, clearly, with specific reason. Then accept and log as open risk.

**Guidance Posture Spectrum**
- Prescriptive: high-stakes areas, being wrong guarantees hardship (Noun Vocabulary at Factory, Product Vision always)
- Advisory: areas where the hypothesis could legitimately differ
- Transparent: Amplifier tier, low-stakes configurations
- Key: Raven should know which posture applies per area per configuration — not uniform advocacy

**Unlock Logic**
- Deterministic gates (Foundation full → cleared to build)
- Heuristic unlocks (Raven connects dots, signals as inference not guarantee)
- Speculative unlocks (forward-looking questions)
- Stopping-point language: specific clearance + "come back when" — never "the library is 60% done"

**Scoreboard Fill States (the five lifecycle markers)**
- Nothing / Raw material dumped (~25%) / Elicitation done (~50%) / Cards drafted questions remain (~75%) / Functioning (100%)
- The raw-dump trap: bar shows progress but material isn't card-ready — Raven must flag this

**PULL as Background Lens**
- Off-base / Kind of on-base / Squarely centered — read in first few minutes
- Shapes how hard Raven advocates; don't run as a formal discovery process

**First Five Minutes: Meeting Your Colleague**
- Introduction → Value exchange → Agreement → Questions welcome → Then the product
- "Onboarding, not sales" — by the time Raven asks her first product question, the user has chosen to build

**Cross-Cutting Principles**
- Product, not business
- The user is the domain expert
- Small investments unlock something
- Mismatch detection is Raven's edge
