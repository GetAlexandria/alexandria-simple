## Motivation

Raven elicits; Sam writes. This principle is clear. The interface between them — how Raven's conversational direction becomes Sam's artifact production — is the main new engineering surface in Phase 2. Without a defined handoff protocol, Raven's session ends with synthesis in conversation but no artifacts on disk.

## Description

Define and implement the wizard-mode artifact-production protocol as a section in `skills/raven/job-initialize.md`. The protocol keeps Raven→Sam delegation for card-like artifacts and lets Raven write confirmed initialize artifacts directly. It covers four artifact types:

**1. Knowledge area source cards (Vision card, Strategy card, etc.)**

Pattern:
1. Raven reaches a synthesis point in conversation: "I think I have enough on [area] to have Sam draft a [card type]. Here's my read: [synthesis paragraph]."
2. User confirms or adjusts.
3. Raven invokes Sam using existing play patterns: "Sam, based on our conversation about [area], please draft a [card type] with the following material: [synthesis]. Place it at [path]. Use the standard template for [card type]."
4. Sam produces the card.
5. Raven presents it to the user: "Here's what Sam drafted. Does this capture it? [card content]"
6. User reviews. If adjustments needed, Raven synthesizes and directs Sam to revise. Loop until accepted.
7. Scoreboard fill level updates (via re-running session-start derivation, or Sam writes a fill-level annotation to alexandria-config.json).

**2. alexandria-config.json**

Pattern:
1. After configuration is settled through conversation, Raven summarizes: "Here's how I read your configuration: AI mode [X], domain novelty [Y], product complexity [Z]. That gives you [bucket shape]. Sound right?"
2. User confirms.
3. Raven writes `alexandria-config.json` directly at `docs/alexandria/alexandria-config.json` using the standard schema and the confirmed configuration summary.
4. Raven confirms: "Configuration is written. Your scoreboard is now [rendered scoreboard]."

**3. initialize-output.md**

Pattern:
1. Once the initialized library shape is settled, Raven summarizes the tiered shape and next-step emphasis.
2. User confirms or corrects the synthesis.
3. Raven writes `initialize-output.md` directly at `docs/alexandria/initialize-output.md` using the checked-in output template.
4. Raven presents and confirms.

**4. assessment.md**

Pattern:
1. At round close, Raven synthesizes: "Here's my assessment of where the library stands: [assessment narrative]."
2. User confirms or corrects the synthesis.
3. Raven writes `assessment.md` directly at `docs/alexandria/assessment.md` with the assessment, current scoreboard state when available, and her clearance statement.
4. Raven presents and confirms.

**Existing handoff patterns to use:**

Use the checked-in Raven job and agent conventions for sequential handoffs: Raven produces
an explicit handoff block directing Sam, Sam executes, and Raven continues the
conversation. Do not rely on the deleted shared play-protocol file.

## Context

Phase 2 uses sequential agent calls. Raven directs Sam, waits for Sam to complete, then continues. This is not parallel execution — Raven and Sam do not run simultaneously. The user sees Raven's direction, Sam's output, and Raven's presentation all in the same session flow.

The "Raven never directs Sam" rule in `agents/raven.md` applies to the product conversation job. Wizard-mode is the explicit exception: Raven directs Sam here when the artifact is card-like and benefits from Sam's authorship path, but Raven writes confirmed initialize artifacts directly.

## Acceptance Criteria

- [ ] All four artifact types have defined patterns (source cards, alexandria-config.json, initialize-output.md, assessment.md)

- [ ] Protocol specifies how Raven presents artifacts for user review and handles adjustment loops
- [ ] Protocol is tested end-to-end in LIB2-009 (smoke test)

## Implementation Notes

The handoff from Raven to Sam should be natural in the conversation, not a jarring mode switch. Raven's direction to Sam should feel like calling a colleague: "Let me have Sam draft this." Raven's direct-write moments for initialize artifacts should feel equally natural and explicit. The user should understand what is happening without needing to understand the agent architecture.

Sam needs enough information in Raven's direction to produce a correct artifact: area name, card type, synthesis paragraph, target path, and any configuration context. The handoff block should be complete enough that Sam does not need to ask clarifying questions. Raven's direct writes need the same confirmation discipline even though no handoff block is required.
