## Motivation

Raven's current agent definition has one job: Product Conversation. Wizard-mode is a distinct job with a different goal, different tools, different stopping criteria, and a different relationship to Sam. Without a wizard-mode job entry and procedure file, the `/library` entry point (LIB2-001) routes to Raven with no procedure to follow.

## Description

Two deliverables:

**1. Add wizard-mode to Raven's job dispatch table** (`agents/raven.md`):

```
| 2 | Wizard Mode — Library Configuration | `${CLAUDE_PLUGIN_ROOT}/skills/raven/job-initialize.md` | Invoked via /library skill |
```

**2. Create `skills/raven/job-initialize.md`** — the procedure file for wizard-mode. This file covers:

**Goal statement:** Configure the product knowledge library through conversation. Produce alexandria-config.json, an initial set of source cards, and an assessment.md. Update the scoreboard to reflect what was built.

**Session start:** (placeholder — detailed in LIB2-006, but job-initialize.md must reference it)
- Read alexandria-config.json if it exists
- Read library state
- Render scoreboard via the scoreboard tool
- Orient: first-time or returning?

**Conversational configuration procedure:**
- Run the first-five-minutes sequence (introduction, value exchange, handshake, questions-welcome, then-the-product)
- Surface the Frankenstein diagnostic early: "If I were going to prototype something like yours, what would I grab?"
- Derive AI mode, domain novelty, product complexity through conversation — not as a form
- When configuration feels solid, confirm with the user and direct Sam to write alexandria-config.json

**Delegation to Sam:** (placeholder — detailed in LIB2-007)
- Pattern: Raven presents a synthesis → user confirms → Raven directs Sam → Sam produces artifact → Raven presents to user → loop

**Stopping-point calls:**
- Reference the scoreboard explicitly in clearance statements
- Distinguish deterministic gates (Foundation >= 80% → Core unlocks) from heuristic unlocks (Raven's judgment)
- End every round with: specific clearance + "come back when" prompt

**What Raven does NOT do in wizard-mode:**
- Write files directly
- Skip the first-five-minutes sequence
- Present configuration questions as a numbered list or form

## Context

Raven's existing job-product-conversation.md is the reference for job procedure format. The wizard-mode job procedure is longer and more structured because it has explicit phases (session-start, configuration, delegation, stopping-point) rather than a free-form product conversation.

The Division of Labor section in `agents/raven.md` currently says "You never direct Sam." This needs to be updated for wizard-mode: in wizard-mode specifically, Raven does direct Sam — this is the one job where that applies.

## Implementation Notes

Keep the job procedure as procedure text, not embedded code. Raven reads procedure files; she does not execute them programmatically. The procedure should be specific enough that Raven can follow it without ambiguity, but written in natural language directive form — not a markdown checklist she reads to the user.
