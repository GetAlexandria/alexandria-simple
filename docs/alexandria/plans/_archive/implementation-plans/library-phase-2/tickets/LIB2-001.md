## Motivation

Every other Phase 2 ticket depends on `/library` being a real, registered skill. This is the entry point through which all wizard-mode sessions begin. Without it, there is no Phase 2 user experience to build toward.

## Description

Create `skills/library/SKILL.md` as a thin skill file that invokes Raven in wizard-mode. The skill itself does no orchestration — its entire job is to establish context and hand off to Raven's wizard-mode job. Raven's job procedure (LIB2-004) will contain the actual session logic.

The skill file should:
- Include a `requires:` frontmatter block appropriate for wizard-mode (high reasoning, medium adherence — Raven needs to adapt to user responses, not walk a fixed script)
- Describe the skill in the `description:` field: "Your persistent library configuration room. Raven reads your current library state and picks up where you left off."
- In the body: establish that Raven is running in wizard-mode, reference her wizard-mode job file, and hand off cleanly
- Not repeat orchestration logic that belongs in Raven's job procedure

## Context

Compare to how other skills invoke agents — the skill file is a thin context-establisher, not a procedure itself. The existing `/wizard` skill (`skills/initialize/SKILL.md`) is the Phase 1 equivalent; `/library` is the Phase 2 entry point that routes through Raven's agent architecture rather than a standalone skill procedure.

The existing `/wizard` skill must remain functional. `/library` is additive, not a replacement. Both can coexist — `/wizard` for scripted/CI paths, `/library` for live human sessions.

## Acceptance Criteria

- [ ] `skills/library/SKILL.md` exists and is registered as a skill
- [ ] Invoking `/library` in a Claude Code session loads the skill without error
- [ ] `requires:` frontmatter is present with appropriate capability levels
- [ ] Skill body establishes wizard-mode context and references Raven's job file
- [ ] Skill does not contain session orchestration logic (that belongs in LIB2-004)
- [ ] Existing `/wizard` skill is unaffected

## Implementation Notes

The `requires:` block for wizard-mode Raven: reasoning should be `high` (she's adapting a session to a user in real time), adherence `medium` (she follows a procedure but with judgment about pacing and emphasis), precision `medium` (artifact quality matters but conversation doesn't need to be clinically precise), volume `low` (wizard-mode is dialogue-heavy, not bulk output).
