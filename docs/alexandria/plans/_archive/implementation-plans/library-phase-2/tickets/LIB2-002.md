## Motivation

The scoreboard is the shared reference between Raven and the user. For it to be trustworthy, the algorithm that derives fill levels from library state must be defined precisely and consistently. Without a spec, LIB2-003 (the renderer) has nothing to render from, and LIB2-006 (session-start) cannot compute state.

This is an enabler ticket — it produces a specification document, not production code.

## Description

Document the scoreboard derivation algorithm in `docs/initialize/scoreboard-derivation.md`. The spec must define:

**Inputs:**
- `alexandria-config.json` — which knowledge areas are active, which tier (Foundation/Core/Amplifier) each belongs to
- Library state — cards present, Conan grades on those cards, source files in `docs/context-library/sources/`

**Fill-level states (five, mapping to expert calibration lifecycle markers):**

| Level | Approximate % | Detection Criterion |
|-------|---------------|---------------------|
| Nothing | 0% | No cards, no source material for this area |
| Raw material dumped | 25% | Source material exists but is incomplete for card-building (no cards built yet, or source flagged as thin by Raven) |
| Elicitation done | 50% | Source material complete; no cards built yet |
| Cards drafted, questions remain | 75% | Cards exist but Conan grades them below threshold, or Raven has logged open questions for this area |
| Functioning | 100% | Cards exist AND pass Conan's quality threshold for this area |

**Ambiguous cases to specify:**
- Multiple cards per knowledge area: aggregate by weakest card? average? the spec must decide.
- Partial cards (some sections present, others absent): count as 75% if any card exists for the area?
- Source material without cards: distinguish "thin dump" (25%) from "complete, awaiting card build" (50%) — what signal distinguishes these?
- Knowledge area present in alexandria-config.json but with no matching card type in the library: treat as 0%.

**Bucket-level aggregates:**
- Foundation fill % = mean of all Foundation-tier area fill levels
- Core locked condition: Foundation mean < 80%
- Clearance messages: which specific areas must be at ≥ 100% (not just average) for full Foundation clearance?

## Context

From the expert calibration material: "The ~25% state is a common trap. Someone dumps a document into the library, the bar shows progress, but the material isn't complete enough for cards to be built from it." The spec must give Raven enough signal to distinguish raw-dump from complete source material.

The spec does not need to be perfect before LIB2-003 can start — the renderer can work with a draft spec. But the spec must be stable before LIB2-006 (session-start) ships, because session-start depends on derivation being correct.

## Acceptance Criteria

- [ ] `docs/initialize/scoreboard-derivation.md` exists
- [ ] Five fill-level states are defined with detection criteria for each
- [ ] Ambiguous cases (multiple cards, partial cards, thin source material) are resolved with a decision and rationale
- [ ] Bucket-level aggregate formulas are specified (Foundation %, Core lock condition)
- [ ] Spec reviewed against at least two real configurations (Factory-High, Short-Order-Cook-Low) and produces sensible results

## Implementation Notes

Start from `docs/initialize/initialize-engine.yaml` to understand what knowledge areas exist and how they map to tiers per configuration. The spec should be readable by both implementation code and by Raven herself — she will reference it to explain fill levels to users.
