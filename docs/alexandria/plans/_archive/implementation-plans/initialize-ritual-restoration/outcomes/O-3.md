## Validation Criteria

- First-session job creates a Task per ritual beat using TaskCreate, with explicit blocks/blockedBy dependencies
- TaskUpdate transitions tasks through in_progress → completed in beat order
- Prose procedure file remains the canonical spec; when Task primitives are unavailable (non-Claude-Code harness), the job degrades gracefully to prose execution with no user-visible failure
- Eval harness asserts Task lifecycle on Claude-Code runs (tasks created in order, completed in order, no tasks skipped)
- ADR checked in documenting the execution-aid-with-fallback contract

## Motivation

Prose-adherence-under-load is exactly the failure mode that degraded the old ritual. Tasks convert procedure from prose-plus-hope to data-plus-harness-enforcement. Tasks also make progress visible to the human, restoring the sense that "the expert has a plan." The fallback contract preserves Alexandria's any-harness portability commitment.
