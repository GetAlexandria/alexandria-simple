## Validation Criteria

- `Standard - Card Frontmatter Schema` exists in `docs/alexandria/library/rationale/standards/` and documents the active stored schema plus deferred field rules
- `parseCardFrontmatter` in `packages/ax/src/lib/frontmatter.ts` recognizes fields used by shipped readers without adding unused typed fields
- Unknown fields parse leniently (do not throw)
- The Standard card is referenced by every reader that will consume the schema (lint, health-check, scoreboard-derive, ax cards list)
- Existing card types (Standards, Principles, etc.) that already have partial or legacy frontmatter continue to parse leniently without promoting unshipped fields into the typed schema

## Motivation

Card frontmatter has been growing organically: `type:` was added during the
type-claim taxonomy work, and other ad hoc fields have appeared without a
clear writer and reader contract.
The active stored schema keeps only fields that are written and consumed by
shipped workflows. Computable facts (`layer`, built status) and lifecycle
states that need shared data (`missing`, `retired`) stay out of card-local
frontmatter. Relationship edges also stay out of this schema until the library
has a graph edge model rich enough to capture `WHERE` sections completely.
Provenance fields such as `source` and `classification_rationale` wait for a
horizontal writer + reader slice.

Without a documented schema, every reader implements its own subset and they
drift. Without a shared parser stance, documentation can quietly diverge from
runtime behavior. This outcome lands the active schema rule so the rest of Phase
1 (filters, migrations, area binding) has a foundation to build on.
