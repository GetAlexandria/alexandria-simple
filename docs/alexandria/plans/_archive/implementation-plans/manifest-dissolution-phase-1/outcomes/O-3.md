## Validation Criteria

- `packages/ax/src/tools/lint-manifest.ts` Sweep 4 inventory checks consume `ax cards list --json` output for the on-disk side; `manifest.md` is still parsed for the expected-cards side (until Phase 2)
- `packages/ax/src/tools/health-check.ts` inventory reads route through `ax cards list --json`; expectation_source remains `inventory_manifests` for the gap half
- The `Agent - Conan` prompt instructs Conan to call `ax cards list`, `ax cards list --summary`, and `ax config show` for inventory queries instead of reading `manifest.md` inventory tables
- The stale reference in `packages/alexandria-plugin/docs/initialize/scoreboard-derivation.md` lines 181-182 ("the latest Conan inventory or manifest") is updated to reflect that inventory routes through the CLI
- Existing lint and health-check integration tests still pass after the migration; no behavioral regression on Sweep 4 outputs
- `parseInventoryManifests()` and the `manifest*.md` regex remain in `lint-manifest.ts` (used for the expected-cards side) — they are NOT deleted in Phase 1

## Motivation

The CLI from O-1 is only valuable if the readers that need inventory actually
use it. This outcome migrates every reader for the inventory half: code
consumers (lint-manifest, health-check) and the agent consumer (Conan).

The migration is intentionally partial. `manifest.md` keeps its expected-cards
and judgment tables (the "what should exist" half) because there is no clean
replacement until the beads + ledger data layer arrives. Phase 1 narrows the
manifest's role from "everything" to "expected cards plus judgment notes." That
is enough to make the file dramatically less brittle while staying honest about
what is not yet replaceable.
