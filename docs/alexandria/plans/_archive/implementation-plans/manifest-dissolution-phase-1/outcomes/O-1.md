## Validation Criteria

- `ax cards list` walks `docs/alexandria/library/` and emits one row per card on disk (type, name, layer, path)
- `ax cards list --type Standard` filters by card type case-insensitively and returns only Standard cards
- `ax cards list --layer rationale` filters by layer case-insensitively (derivable from type)
- `ax cards list --area 1.1` filters by frontmatter area once cards are populated
- `ax cards list --json` emits structured JSON consumable by downstream tools with stable `area`, `layer`, `name`, `path`, and `type` keys
- `ax cards list --summary` emits groupBy(type) counts — replaces manifest.md Summary table
- `ax config show` prints the contents of `alexandria-config.json` — replaces manifest.md Header section
- All commands are reachable through the `ax` CLI router and pass black-box integration tests

## Motivation

Today, every reader that needs to know "what cards exist in this library" parses
`manifest.md` — a hand-maintained markdown file. Adding three cards in this PR
required hand-editing two section headers, adding a new section, and updating a
Summary table. That brittleness is mechanical waste.

This outcome introduces the CLI surface that lets readers query the library
directly from filesystem and frontmatter. It is the foundation for migrating
every other reader (lint, health-check, Conan) off `manifest.md` for inventory
queries. Manifest.md keeps its expected-cards and judgment tables until the
beads + ledger data layer arrives.
