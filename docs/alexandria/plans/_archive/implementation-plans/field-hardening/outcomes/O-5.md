## Validation Criteria

- Every user-visible slash command begins with `/ax:` (e.g., `/ax:library`, `/ax:plan`, `/ax:complete-plan`, `/ax:sync-tickets`).
- The Claude plugin manifest `name` field is `ax` (not `alexandria`).
- Install/upgrade path handles the rename: users installed under the old name get a clear migration hint or automatic upgrade.
- CLI smoke tests confirm old command forms produce a deprecation message rather than silent failure.
- Release note documents the breaking change and the migration path.

## Motivation

Currently user commands are a mix: `/library`, `/alexandria:plan`, `/complete-plan`, `/alexandria:sync-tickets`. Users can't tell at a glance which commands belong to Alexandria versus to Claude Code or to another plugin. The Compound Engineering plugin models a cleaner convention — every command carries the plugin namespace. Aligning to `/ax:<skill>` for commands and `ax` for the plugin manifest gives users one prefix to remember, a single grep pattern, and a coherent story in release notes and docs. Half-measures on namespacing never settle; the user-surface rename and the manifest rename should ship together as one breaking change with a release note, not dripped across two releases.
