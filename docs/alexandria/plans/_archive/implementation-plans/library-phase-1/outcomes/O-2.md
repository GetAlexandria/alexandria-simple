## Validation Criteria

- The wizard detects thin-material state during Step 0 routing (no docs, no code, or
  material too sparse for gap analysis to be meaningful)
- Greenfield users are not routed through gap analysis framing
- The greenfield path opens with "Tell me what you're building" and uses the
  conversation to generate starter source material concepts, not a gap list
- The threshold for greenfield detection is clearly specified (not just zero-docs,
  but "not enough material for gap analysis to be a meaningful frame")
- A user with a thin prototype and a few pages of notes hits the greenfield path,
  not the brownfield path
- The wizard's output for a greenfield session is still valid input for downstream
  agents (alexandria-config.json, assessment.md are produced)

## Motivation

The current wizard asks greenfield users to assess gaps in documentation they have
never written. This is structurally wrong — it presupposes a brownfield state. A user
with ideas but no docs doesn't have gaps; they have a product that hasn't been
described yet.

The improvement-opportunities source material (section 2) articulates this precisely:
greenfield means "not enough material for gap analysis to be a meaningful frame." The
right response is elicitation-as-generation: Raven draws out what the user knows
through conversation and turns that into the first draft of source material. The wizard
output still exists; the path to producing it is entirely different.

This is one of the two architectural fixes in Phase 1 — it reshapes what the wizard
does for a significant category of users, not just how it communicates.
