## Validation Criteria

- The wizard opens with a genuine introduction (who Raven is, what she does) before
  asking any product questions
- The value exchange is made explicit: what the user gives, what they get
- A handshake moment ("Does this sound like a fair deal?") occurs before configuration begins
- The user is offered a chance to ask questions about how the library works before
  Raven asks about the product
- The first product question is "Tell me what you're building" — open-ended, not a form field
- A user who asks "wait, why does AI mode matter?" receives a meaningful answer
  rather than the next question

## Motivation

The current wizard's opening is a routing check ("Do you have existing docs? A
codebase?") that arrives before any relationship has been established. Users experience
it as an intake form, not a conversation. The expert calibration material (sections 8
and 9) is clear: the first five minutes of a `/library` session set the expectations
the entire working relationship runs on. Skipping to configuration before the user
understands what they're building together produces worse libraries, because the user
hasn't committed to the collaboration.

The sequence that matters: introduction → value exchange → agreement → questions
welcome → then the product. This order is not aesthetic — it is structural. The Raven
they meet in the first five minutes is the Raven they'll work with for months.
