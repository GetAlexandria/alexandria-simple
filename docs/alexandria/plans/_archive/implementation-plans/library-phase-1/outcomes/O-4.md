## Validation Criteria

- All existing wizard eval cases run without error after SKILL.md changes
- Scores do not regress below baseline on any eval dimension
- If any case scores improve, the new baseline is checked in as part of the PR
- The no-low-ai-low-low case (the currently tracked case) passes structural checks
- No new eval cases are introduced in Phase 1 (new cases are deferred to Phase 2
  when the full conversational experience exists to evaluate)

## Motivation

The build standard requires that skill changes with eval coverage run evals before
merging. A change that regresses eval scores is a failing test even if deterministic
tests still pass. Phase 1 rewrites the wizard skill's opening, greenfield branch,
and question presentation — all of which are exercised by existing eval cases.

This outcome is the gate before merge (FEAT-006). It is "should" in tier because the
underlying changes (O-1, O-2) are the substance; this outcome validates that the
changes don't break what existed before. New eval cases for greenfield onboarding,
brownfield with existing docs, and reconfiguration after AI mode change are deferred
to Phase 2 — after the experience is built and can be played with, following the
"build it, play with it, then harden" eval strategy.
