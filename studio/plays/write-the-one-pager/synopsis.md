## What it does

Produces the one-pager — the durable definition artifact rung 3 consumes —
plus a spoken read-back for the room (100 words is a ceiling, not a target).
It defines the solution on the problem work already done, never re-deriving
it: one coherent direction against the whole problem shape, a coverage map
naming what it addresses and what it explicitly leaves as non-goals, goals
stated as outcomes, and typed success metrics. Where the problem brief
recorded a dispute, the one-pager carries the posited test forward rather
than silently building on one side. It never invents evidence; when the
problem brief is missing, it refuses loudly and routes back to Frame the
Problem.

## Reach for it when

- a problem was just framed and you want to define what to build against it
- you need a crisp one-pager to align the room before scoping begins
- you're handing off to rung 3 and need the definition pinned in writing
- a caller scoped the run and you want the coverage map to honor that narrowing and name what it excluded

## The story

Rung 1 just closed. The Lantern team — the knowledge-library product where
directors turn scattered source material into an approved, banked card library
— is still in the room. Maya's two tangled problems are now a banked problem
brief: sources dying in tabs before the conversion session starts, and
directors re-adding material that's already banked. The dispute about which
drives which is still open; a test is posited but not yet run. Dev leans
forward: **"Raven, write it up."**

What comes back isn't a verdict on the causal dispute. It's a one-pager: a
single solution direction designed against the whole problem shape, with a
coverage map that accounts for both problems — one addressed directly, the
other addressed by way of the shared root, with the posited test carried
forward rather than silently resolved. Goals are stated as changes in the
directors' workflow, not features to ship. The spoken introduction runs to
the delta — the shape of the solution, the coverage verdict, what remains
open — and ends with a question aimed at the weakest point.

## Trigger

**⚡ "Raven, write it up."** — That's the cue. Raven gets the banked problem
brief (rung 1's artifact, the load-bearing input), the saddle (the surface
map and user roster, so the solution direction knows what it's building on),
and the conversation-so-far. She confirms the brief exists before building
anything; if it doesn't, she writes a loud, specific refusal — what she
received, what a problem brief would give the work, and that Frame the Problem
produces one — and stops. She is explicit about what she didn't have: any
input declared missing or TBD in the brief travels as-is into the one-pager,
never backfilled.
