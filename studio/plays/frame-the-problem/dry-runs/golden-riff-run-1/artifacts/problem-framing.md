# Problem Framing — losing source material between discovery and library capture
status: draft (v1)

## The problem(s)

### Good source material dies in browser tabs before it ever reaches the library

- who has it: Maya (and likely other researchers/directors), in the circumstance of doing research across many tabs and then sitting down later to do a conversion session
- evidence:
  - "Every time I'm doing research I end up with like forty tabs, and by the time I sit down to do a conversion session I can't remember which tab had the thing. So stuff just never makes it in." — first-hand: a specific past instance (Maya describes a recurring pattern she personally experiences, grounded in a concrete workflow she does)
  - "Half my best source material dies in tabs." — first-hand: a specific past instance (direct claim about her own repeated experience)
  - "I've watched you do it." — first-hand: a specific past instance (Dev corroborates having directly observed Maya's tab-loss workflow)
- thin spot: Maya describes the pattern convincingly, but no single dated instance is on the table — "last Thursday I had the perfect thread on X and lost it" would make this airtight. The corroboration from Dev ("I've watched you do it") is real but similarly un-pinned.

### Directors don't know what's already in the library, so they re-add things

- who has it: directors using the library, in the circumstance of adding material they believe is new but which already exists
- evidence:
  - "directors keep telling us they don't know what's already in the library, so they re-add things" — assumed / hand-wavey (Maya reports what directors "keep telling us" — no specific director, no specific duplicate, no specific occasion cited)
  - "every director has this problem, literally all of them, I'd bet anything" — assumed / hand-wavey (universal claim with no backing instance)
- thin spot: the entire claim. There is no specific past instance of a director re-adding something already banked. A single concrete example — which director, which piece of material, when — is needed before this problem can be trusted.

## How they relate (a guess)

Siblings — held loosely. Both involve a gap between what a person knows is in the library and what is actually there, but they point in opposite directions: problem 1 is material that should be in the library but isn't; problem 2 is material that is in the library but the user doesn't know it. They could share a root cause (poor visibility into library contents), but that connection is a guess — the evidence so far doesn't prove they're the same problem. Dev flagged this: "That's a different thing though. That's search."

## What this means for the solution (so far)

The proposed solution is a browser extension that addresses both problems (clip-to-library capture and "already banked" detection). The evidence so far:

- **Partially supports** the capture side: Maya's tab-loss pattern is real and corroborated, and "capture-in-the-moment instead of capture-from-memory" is a defensible reframe of her own experience. But the gap between "I lose things in tabs" and "a browser extension is the right fix" has not been earned — the problem could also be solved by a simpler bookmarking flow, a share-target, or changes to the conversion session itself. The solution shape is still a hypothesis.
- **Undercuts** the duplication/search side: this claim has no specific past instance behind it at all. Building "already banked" detection into an extension is premature until at least one concrete duplicate-addition episode is on the table.
