# Problem Framing — losing source material between discovery and conversion
status: draft (v1)

## The problem(s)

### Sources die in tabs before they ever reach the library
- Maya, during research: she opens dozens of tabs, and by the time she sits down
  for a conversion session she can't reconstruct which tab held the material she
  wanted. Source material never makes it in.
- evidence: `first-hand: Dev has directly watched Maya lose sources this way`
  (no single dated instance given, but Dev confirms observed pattern).
  Maya's own testimony: "Half my best source material dies in tabs."
- thin spot: We have Dev's corroboration that this happens, but no specific
  past instance with a concrete cost — e.g., a conversion session that came
  out thin, or a library gap someone later tripped over, because sources were
  lost in tabs.

### Directors re-add material that is already banked
- Directors doing library intake: they can't tell what's already in the library,
  so they bank duplicates.
- evidence: `first-hand: Jules reports that last Tuesday, Priya banked the same
  board deck twice. She caught it only because the Strategy coverage bar
  double-counted — it showed fuller than the area really was. The team almost
  skipped a conversion session because the bar told them they were already
  covered.`
- thin spot: We have one solid instance (Priya / Tuesday). Maya's broader claim
  that "every director has this problem, literally all of them" is
  `assumed / hand-wavey` — it rests on her secondhand read, not named
  instances beyond Priya's.

## How they relate (a guess)

Sibling problems, not parent-child — held loosely. Both stem from the library
being opaque at the moment of action (research browsing for problem 1, intake
for problem 2), but the circumstances and the people affected are different.
Maya's tab-loss is a capture-workflow problem; the re-add problem is a
search/visibility problem. The solution Maya pitched (a browser extension) would
plausibly touch both, but the problems do not require the same fix.

## What this means for the solution (so far)

The browser-extension pitch bundles two problems that may want different
responses:

- **Tab-loss / capture-in-the-moment:** The extension idea directly addresses
  this. Supported by first-hand observation, though the concrete cost of lost
  sources still needs a specific instance. *Lightly supports.*
- **Duplicate banking and misleading coverage bars:** Jules's Priya instance
  is the strongest evidence in the conversation, and it points to a
  library-side visibility problem (knowing what's already banked) — which an
  extension *could* address, but which might be better served by in-product
  search or dedup. The extension is one hypothesis, not the obvious one.
  *Complicates — the solution shape may not match the problem shape.*
- **Severity:** The Priya instance carries a concrete downstream harm (team
  nearly skipped a needed conversion session based on a lying coverage bar).
  The tab-loss problem has not yet surfaced a comparable cost. This is worth
  noticing — the problem Maya considers secondary may carry more demonstrated
  risk.
